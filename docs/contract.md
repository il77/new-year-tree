# Контракт рендера сцены

Как эпик 2–4 добавляет свой объект на сцену. Контракт публикует эпик
`epic-scene`, используют `epic-garland`, `epic-calendar`, `epic-world`.
Один интерфейс на все эпики; контракт — только про способ попадания
объекта в кадр, ничего больше.

Стиль объектов (R12): силуэт — скруглённый, объём — градиент + блик
верх-слева + мягкая тень, свечение — слоями. Гид и рецепты:
[style.md](style.md).

## Как добавить объект

1. Импортируй общий экземпляр контракта:

   ```js
   import { sceneContract } from './contract.js';
   ```

2. На уровне модуля зарегистрируй объект:

   ```js
   sceneContract.register(
     (ctx, width, height, t) => {
       // отрисовка объекта на ctx
     },
     { layer: 20 }, // необязательный слой, по умолчанию 0
   );
   ```

3. Импортируй свой модуль из `src/main.js` (или из уже подключаемого
   модуля). ES-модули выполняются до тела `main.js`, поэтому объект
   попадёт в самый первый кадр `bootstrap`.

Поздняя регистрация (код, выполняющийся **после** загрузки страницы —
обработчик события, отложенный запуск): на странице есть общий
рендер-хэндл `page` из `src/main.js`, вызови его `render()` сразу после
регистрации — объект появится сразу, не дожидаясь ресайза:

```js
import { page } from './main.js';

sceneContract.register(draw, { layer: 20 });
page.render(); // объект на экране сразу после регистрации
```

`bootstrap(doc, win, contract?)` возвращает тот же объект `{ render, contract, ritual }`
(`ritual` — контроллер ритуала первого входа, story 1.3; контракту не нужен),
поэтому вне страницы (в тестах, где `page === null`) кадр вызывается
явно: `const { render } = bootstrap(doc, win, contract); …; render();`.
Переиспользовать `bootstrap` для повторного кадра не нужно — он
подписывает ещё один resize-слушатель.

На самой странице объекты мира регистрирует `src/main.js` сразу после
`bootstrap` (тот же `page.render()`-паттерн, что выше): см. `registerWorld`
в `src/world.js` — слои снег 5 → лес 8 → ёлка 10 под будущей гирляндой 20.

Никакой вёрстки, DOM и зависимостей контракт не добавляет: объект рисует
только на переданном 2D-контексте.

## Параметры draw-функции

| Параметр | Что передаётся |
|----------|----------------|
| `ctx` | `CanvasRenderingContext2D` текущего canvas (в тестах — мок) |
| `width` | текущая ширина canvas в px — считать размеры от неё, не от окна |
| `height` | текущая высота canvas в px |
| `t` | время кадра в мс; `0` — статичный кадр (камера в нуле, transform нет); при `t > 0` камера `src/animation.js` слегка покачивает весь кадр — объекты об этом не знают |

Кадр перерисовывается на старте, на каждом кадре единого rAF-цикла (живая
сцена, story 1.5) и на каждый `resize` окна, поэтому `width`/`height` могут
меняться от вызова к вызову — объект должен пересчитывать свои координаты
от них (как искра: позиция долями экрана). `draw` вызывается до ~60 раз в
секунду: никакой тяжёлой работы на кадр.

## Порядок отрисовки

Один кадр рисуется строго в таком порядке:

1. **Фон** — чёрный `#000` на весь кадр.
2. **Искра** — `drawSpark` в своей точке (центр-выше).
3. **Объекты контракта** — по возрастанию `layer`; при равенстве слоя —
   в порядке регистрации (стабильно). Отрицательные слои допустимы, но
   объект всё равно рисуется **после искры**: искра всегда между фоном
   и слоями контракта.

Слои координируются между эпиками, контракт их не назначает. Скелет
слоёв эпика 4 (фон → ёлка → огоньки → слои мира) разрешается без знания
содержимого объектов:

```js
sceneContract.register(drawTree, { layer: 10 });      // ёлка
sceneContract.register(drawLights, { layer: 20 });    // огоньки гирлянды
sceneContract.register(drawWorldLayers, { layer: 30 }); // слои мира
```

Значения 10/20/30 — рекомендация, не правило: контракту важен только
относительный порядок.

## Ошибки

Невалидная регистрация падает сразу с понятным `TypeError`, а не молча
ломает кадр:

- `register()` без функции / с не-функцией →
  `register: нужна draw-функция (ctx, width, height, t), получено: …`
- `options` не объект (число, строка, …) или `null` →
  `register: options должен быть объектом { layer }, получено: …`
- `layer` не конечное число (строка, `NaN`, …) →
  `register: layer должен быть конечным числом, получено: …`

После ошибки объект **не** зарегистрирован (`contract.size` не изменился).

## Тестирование своего объекта

Контракт — фабрика без глобального мутабельного состояния. В тестах
создавай изолированный экземпляр и передавай его явно:

```js
import { createSceneContract } from '../src/contract.js';

const contract = createSceneContract();
contract.register(myDraw, { layer: 10 });
bootstrap(doc, win, contract);   // или renderFrame(ctx, w, h, t, contract)
```

Общий `sceneContract` в тестах не регистрируй — состояние делилось бы
между тестами страницы.

## Границы контракта

Контракт **не** содержит: объектов гирлянды/календаря/мира (scope
эпиков 2–4), анимации сцены (живая сцена — `src/animation.js`, story 1.5),
ритуала входа (story 1.3). Он только
публикует способ регистрации и порядок отрисовки.

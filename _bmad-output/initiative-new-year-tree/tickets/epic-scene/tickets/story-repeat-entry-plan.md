## Intent

**Problem:** После первого ритуала (story 1.3) не доказано, что повторное открытие страницы действительно мгновенное и без преград (R2/R10): нужно закрыть строку матрицы — с флагом `ny_tree_first_visit = "1"` страница открывается сразу в готовом мире, ритуал не играется, ничего лишнего не мелькает и не запускается.

**Approach:** Большая часть поведения уже построена в 1.3 (флаг читается в `bootstrap` через `readFirstVisit`, revealed-фаза с первого кадра, касания — no-op). Эта story доводит до конца: (1) закрывает найденный пробел — подпись «зажги» могла мелькнуть до загрузки отложенного модуля (синхронный инлайн-скрипт в `index.html` скрывает её при уже стоящем флаге, до первого кадра); (2) доказывает всё тестами в новом `test/repeat.test.js` — полный цикл «первый вход → повторное открытие», полный no-op касаний при revealed, точное отсутствие rAF-цикла и лишних кадров, деградации.

## Boundaries & Constraints

**Always:** ноль зависимостей (node:test, мок-ctx и стабы — образцы в `test/ritual.test.js`); не ломать 28 существующих тестов (старые тесты не меняются); вход тихий (R10): без поп-апов, звуков, действий сверх «мир уже есть»; `npm test` и `npm run build` зелёные; git-операции не выполняет агент.

**Never:** никаких поп-апов/звуков/клавиатурных ловушек; никакой постоянной анимации (scope story 1.5); не менять тайминг и фазы ритуала 1.3; не трогать `sceneContract` на уровне модуля в Node-тестах (общий экземпляр — `contract.test.js size === 0` остаётся истиной); R12 — новых объектов рендера не ожидается.

## Implementation Notes

- **Пробел, найденный при разборе:** `<script type="module" src="./src/main.js">` — отложенный: при сетевой загрузке первый paint может случиться до его выполнения, и на повторном входе подпись «зажги» мелькнула бы поверх готового мира (ровно «лишнее», которого требует избежать R2). CSS/`hidden` по умолчанию не годится — старый тест `matrix.test.js` справедливо требует подпись видимой по умолчанию для первого входа. Решение — синхронный инлайн-скрипт в разметке: выполняется в потоке парсинга, до первого кадра, и не зависит от загрузки модуля.
- **Дублирование ключа (`ny_tree_first_visit`/`"1"` в HTML) закрывается тестом:** `test/repeat.test.js` сверяет литералы инлайн-скрипта с `FIRST_VISIT_KEY`/`FIRST_VISIT_VALUE` из `src/ritual.js` и исполняет извлечённый код на стабах (флаг `"1"` → скрыт; прочее/ошибка → виден, без падения).
- **«Никаких лишних кадров» — точный счёт, не «на глаз»:** каждый `render` даёт ровно один `fillRect` фона. Три статичных кадра (bootstrap → регистрация мира → resize) и ноль запланированных rAF — доказательство, что цикл при повторном входе не запускается.
- **No-op касания проверяется по счётчику вызовов ctx:** `ctx.calls.length` до/после касаний не меняется — сильнее, чем «фаза не изменилась»: не было ни рендера, ни альфы, ни записи.

## Design Notes

**Почему не выносить слушатели касаний при revealed.** Слушатели висят всегда, при revealed — идемпотентный no-op (`ritual.touch` не стартует из `revealed`). Условная привязка/отвязка слушателей усложняла бы `bootstrap` без выигрыша: обработчик не рисует, не пишет и не планирует кадры — это проверяется тестом по счётчику вызовов.

**Почему подпись скрывает HTML, а не JS.** Модуль `type="module"` отложенный по спецификации: разметка парсится и может быть отрисована раньше, чем выполнится `bootstrap`. Инлайн-скрипт без атрибутов — синхронный, работает в том же тике парсинга; это единственный способ гарантировать «ничего лишнего» до самого первого paint. Поведение при ошибке хранилища идентично `readFirstVisit`: не смог прочитать — не скрывай, ритуал сам разберётся.

**Курсор.** `pointer` — тихая affordance только в фазе `dark` (ставится в `bootstrap`, снимается при старте ритуала); при `revealed` (повторный вход) он не ставится вовсе — страница не обещает действия, которых не будет.

**Тесты — отдельным файлом.** `test/repeat.test.js` живёт отдельно от `test/ritual.test.js`: 1.3 — про машину состояний и тайминг, 1.4 — про сценарий «второго открытия» (общий storage между двумя `bootstrap`, счёт кадров, no-op). Общие стабы дублируются по образцу, уже принятому в проекте (`createHarness`/`createMockCtx` живут отдельно в `matrix.test.js` и `ritual.test.js`); старые тесты не меняются.

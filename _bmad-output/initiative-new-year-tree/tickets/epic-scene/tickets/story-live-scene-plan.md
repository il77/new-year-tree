## Intent

**Problem:** Сцена статична после проявления: в `src/world.js` `drawSnow`/`drawForest`/`drawTree` принимают `t`, но содержательно его не используют (`void t`), а rAF-цикл из story 1.3 останавливается на `revealed` — после ритуала страница «умирает». Требование R11 («сцена всегда в движении: снег падает, огоньки мерцают, камера слегка покачивается») не закрыто, и Verify story требует доказательства непрерывного движения тестом анимационного цикла при живом ритуале 1.3.

**Approach:** (1) Чистое ядро анимации — новый `src/animation.js`: детерминированные по `t` функции `cameraAt(t)` (sinusoidal сдвиг/поворот/дыхание), `flakeState(flake, t)` (падение с wrap по полосе + боковая качка + мерцание), `twinkleAt(t, period, phase)` (мягкое мерцание огоньков). (2) Обвязка — один rAF-цикл в `src/main.js`: тот же `scheduleFrames` гонит и ритуал, и постоянную анимацию, стартует, когда есть что анимировать (касание в `dark` или `revealed` с первого кадра), после `revealed` не останавливается; пауза по `visibilitychange`. (3) Камера — в `renderFrame` (`src/scene.js`) вокруг искры и объектов контракта, при нейтральной камере (`t = 0`) transform не вызывается вовсе. (4) Мир — снег падает/мерцает (`src/world.js`), на ёлке мерцают декоративные огоньки (R11: «огоньки мерцают»; гирлянда-вклад эпика 2 остаётся слоем 20 поверх).

## Boundaries & Constraints

**Always:** ноль зависимостей (node:test, мок-ctx и стабы по образцу `test/ritual.test.js`); один rAF-цикл на странице; поведение анимации time-based (не зависит от частоты кадров); тихий вход R10 — без звуков, вспышек, рывков (амплитуды/альфы ограничены константами и проверяются тестом); R12 — движение объёмно-гладкое, новые объекты (огоньки) рисуются градиентами-ореолами, радиусы ≤ 10 px, чтобы не путаться со свечением искры в тестах; тайминг ритуала `RITUAL_TIMING` не трогается; деградации 1.3/1.4 сохраняются (нет rAF / нет canvas 2D — без анимации, остальное работает); `npm test` и `npm run build` зелёные; git-операции не выполняет агент.

**Never:** не останавливать цикл на `revealed` (это и есть живая сцена); не запускать цикл в фазе `dark` (анимировать нечего — порог-ритуал остаётся тихой статикой, R9/R10); не планировать второй цикл (touch/resume/bootstrap → `looping`-guard); не менять API `bootstrap` → `{ render, contract, ritual }` и контракт `(ctx, width, height, t)`; не трогать общий `sceneContract` в Node-тестах; не добавлять `Math.random` и глобальное состояние.

## Implementation Notes

- **Почему цикл не стартует в `dark`:** в тёмной фазе сцены ещё нет (слои = 0, искра статична) — крутить rAF означало бы рисовать пустой чёрный кадр 60 раз в секунду и ломать смысл порог-ритуала (R9/R10: тишина до касания). Цикл один (`scheduleFrames` + guard `looping`), но у него два честных триггера: касание (ритуал) и bootstrap при уже готовом мире (повторный вход). Требование «движение не останавливается, пока открыта страница» выполняется с момента появления сцены и дальше — безостановочно.
- **Один цикл, не два:** ритуальная часть интегрирована в тот же `frame` (`ritual.update(t)` → `render(t)` → перепланирование). Дублирование цикла из 1.3 убрано: `revealed` больше не является точкой останова, только guard'ом флага.
- **Time-based:** все формулы — чистые функции от `t` (мс); ни один расчёт не завязан на счётчик кадров, поэтому при 30/60/120 Гц картина одна и та же, а после паузы вкладки движение продолжается с того же «мирового» времени (тайминг ритуала тоже wall-clock — пауза его не ломает).
- **Камера — вокруг контракта, фон — нет:** `#000` заливается до трансформации, поэтому поворот/сдвиг не оставляют щелей; искра и объекты эпиков 2–4 качаются вместе (вся сцена), ничего не зная о камере. `cameraAt(0)` нейтральна по построению (все синусы нулевые) — статичный кадр по контракту не несёт transform-вызовов, это и экономия, и гарантия не трогать старые статичные тесты.
- **Градиенты:** пересоздание на кадр неизбежно (позиции движутся, чистые функции не кэшируют), но кадр экономится там, где можно: пустые слои пропускаются (`alpha ≤ 0`), transform применяется только при нейтральной камере, цикл один, в `dark` цикла нет.

## Design Notes

**Архитектура цикла: один rAF на странице, два честных триггера.** `scheduleFrames()` из 1.3 переиспользован без дублирования: guard `looping` гарантирует максимум один pending-кадр, `frame` — единственная точка перепланирования. Ветки: (1) касание в `dark` → старт (ритуал); (2) bootstrap при `revealed` → старт (повторный вход — живая сцена сразу); (3) `visibilitychange` → возобновление, только если фаза ≠ `dark`. На `revealed` цикл **не** останавливается — это и есть story 1.5; остановка только при скрытой вкладке (CPU) и при отсутствии rAF/2D.

**Почему камера не маскируется по фазе ритуала.** Амплитуды крошечные (≤ 3 px сдвига, ≤ 0.16°), а мир в первые ~200 мс ритуала ещё не виден (альфа слоёв ≈ 0) — маскировка добавила бы состояние «амплитуда × прогресс» без выигрыша, но с риском для доказательства «тайминги не тронуты».

**Overscan вместо абсолютного «щелей нет».** Фон залит до трансформации, но сдвиг + поворот + минимальный scale `0.994` могли втянуть край снежного поля внутрь кадра на ~5–6 px — медленно осциллирующая чёрная полоска у нижнего/бокового края. Вместо ослабления комментария контент масштабируется на `CONTENT_OVERSCAN = 1.02` (внутри той же трансформации, вокруг центра): +2% перекрывает худший отъезд (8 px запаса по вертикали против 5.4 px худшего случая), на глаз незаметно. Статичный кадр `t = 0` по-прежнему без transform — старые тесты не тронуты.

**Огоньки ёлки — почему слой ёлки, а не новый слой.** Декоративные мерцающие огоньки принадлежат ёлке (рисуются в `drawTree`, слой 10); будущая общая гирлянда (слой 20, эпик 2) ляжет поверх и не конфликтует. Радиусы ореолов ≤ 10 px — осознанное ограничение: фильтр старых тестов «свечение искры» — `10 < r < 30`, огоньки не маскируют проверку «искры в готовом мире нет».

**`visibilitychange` — решение.** Останавливаем (не перепланируем кадр), возобновляем по событию; `doc.hidden === true` — guard для стабов без свойства, `typeof doc.addEventListener === 'function'` — guard для стабов без DOM. Если браузер приостановил rAF сам (вкладка скрыта), pending-кадр либо не выстрелит (тогда по возврату его продолжит браузер), либо выстрелит и увидит `hidden` → остановит цикл; `looping`-guard исключает двойной цикл в обоих сценариях. Пауза не ломает тайминги: и ритуал, и снег живут по wall-clock `t`.

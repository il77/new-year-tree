## Intent

**Problem:** Story 2.1 дала один огонёк и общий счётчик, но правило R4 ещё не работает: каждые 10 входов должны схлопываться в один большой огонёк, а заполненная ёлка — давать сильное сияние всей целиком.

**Approach:** Сервер хранит только агрегаты входов файлом: общее число, число полных десятков и остаток. Клиент получает агрегат в том же ответе и одним объектом контракта рисует нужное число мелких и больших огоньков по ярусам ёлки; при достижении порога заполнения добавляет тёплое сияние вокруг ёлки. Всё на 2D Canvas, без зависимостей.

**Decision (2026-11-22, by human):** ёлка считается заполненной при **300 входах**; сильное сияние включается при `count >= 300`, ниже порога его нет.

## Boundaries & Constraints

**Always:** ноль зависимостей, Node 22+, тесты на `node:test`; состояние — файл в `data/`, не в `dist/`, не в коммите; ключи `count` и `seed` и поведение GET без увеличения счётчика сохраняются; ни один визит не отклоняется; ровно одна регистрация в контракте на слое 20 и один rAF-цикл; тёмная фаза ритуала остаётся тёмной (`tree <= 0` — огоньков нет); R12 — скруглённые силуэты, градиент, блик верх-слева, мягкое свечение, ни одного `fillRect` у объектов сцены.

**Never:** не хранить список отдельных визитов; не делать БД, новый рантайм-пакет, второй цикл рендера; не менять ритуал, контракт, слои 5/8/10 и адрес деплоя; не делать раскладку по seed, цвет дня недели (story 2.3), исправления ретро (story 2.4/2.5) и публикацию (story 2.6).

- Given два браузера, when в одном происходит вход, then оба после обновления видят одинаковые `count` и агрегат, одной гирляндой.

## Design Notes

Большой огонёк — тот же шар `drawLight` с увеличенным радиусом и ореолом, не новая сущность. Сияние — один радиальный градиент по центру ёлки с тремя стопами из мока; объект не рисует прямоугольник. Раскладка в этой истории детерминированная по номеру слота; чистые seed и день недели остаются за story 2.3.
